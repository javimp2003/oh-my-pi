Stage a change to one file of an omp skill: exact `old_text` → `new_text` (must match exactly once). Nothing is written now: your staged changes to a skill become one proposal the user reviews, then approves or rejects. Calls on the same file build on each other. `file` is relative to the skill directory (default `SKILL.md`).
SKILL.md keeps its frontmatter `name`; `description` stays third person, ≤1024 characters; body ≤500 lines.
`summary`: one line for the user — what the skill will now get right.
`reason`: for the user — the evidence in the transcript that makes this change necessary (what happened, what showed the right version).
